# DB-03 — проект для независимого аудита

**Обезличенный код:** DB-03  
**Предметная область:** управление проектами и задачами  
**Назначение:** исследование исходного студенческого проекта на семи турах DB Audit Challenge.

## Порядок работы

1. Используйте отдельную тестовую БД PostgreSQL; скрипты могут удалять ранее созданные объекты.
2. Изучите `schema.sql`, затем запустите `seed.sql` (порядок и конфликты объектов определите до выполнения).
3. `tests.sql` проверяйте на копии данных: в некоторых скриптах есть отрицательные операции и psql-команды.
4. Аналитику и оптимизацию проверяйте по приложенным SQL и собственным запросам.
5. Все выводы аудитора подтверждайте SQL, текстом DDL или воспроизводимыми действиями.

## Состав
- `analytics.sql`
- `performance.sql`
- `schema.sql`
- `seed.sql`
- `tests.sql`
- `МОДЕЛЬ_СУЩНОСТЕЙ.md` — список таблиц, извлечённый из схемы.

## Семь туров

1. Архитектура: проверьте типы сущностей и связи; не принимайте список таблиц за готовую ER-модель.
2. Аномалии: исследуйте данные и тестовый файл `ОБЩИЙ_ДАТАСЕТ_800.csv` из общего комплекта как **отдельную задачу**; наличие автоматической миграции именно этих 800 строк **не заявляется**.
3. Нормализация: оцените зависимости и ключи в `schema.sql`.
4. Устойчивость: используйте `tests.sql`, проверяйте в транзакциях на копии базы.
5. Бизнес-правила: восстановите правила по ограничениям и оцените достаточность реализации.
6. Аналитика: используйте аналитические и производительные запросы, оценивая план на реальных данных.
7. Заключение: подготовьте три обоснованных замечания, дайте автору возможность возразить.

## Ограничения проверки

- Оригинальный авторский отчёт и встроенные изображения намеренно не передаются, чтобы не раскрыть личность автора.
- `migration.sql` не включён: не следует объявлять потери при миграции доказанными без воспроизводимого сопоставления.
- Запуск на реальном сервере PostgreSQL в ходе подготовки комплекта не выполнялся: совместимость и результаты SQL требуется проверить перед занятием.
